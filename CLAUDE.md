@AGENTS.md

## Optional shortcut words (Claude Code)
Shortcuts for the steps in AGENTS.md. The rules never depend on them; without them, follow AGENTS.md directly. `<n>` is the issue number.
- `issues` — list `ready` and `in-progress` issues grouped by module label, then `idea` issues under "Ideas"; nothing else.
- `<n>` — claim the issue (assign yourself, or comment if you cannot; `gh issue develop <n> --checkout --name <n>-<slug>`), show it, propose a tier with a one-line reason and wait. Tiers: fix = implement, check, report · feature = short plan in chat, wait for OK, implement · plan = write `docs/plans/issue-<n>.md`, commit, stop.
- `execute` — run `docs/plans/issue-<n>.md` for this branch step by step, checking each.
- `finish` — re-read the acceptance criteria against the work; if any is unmet, stop and list them. Otherwise run the checks of every module touched, commit, push, open or update the PR per AGENTS.md with the `Tier:`, `Next action:` and `Verification run:` lines, and mark it ready (draft → ready). Do not enable auto-merge: the independent review does that on `pass`. Then `gh pr checks --watch` ("no checks" is never green: wait 30 s and check again). If CI fails: `gh run view <id> --log-failed`, fix, push, watch again — at most two rounds, then stop and show the failure. Report the PR URL, a file-by-file diff summary and the `Verification run` line, and say the PR waits for an independent review.
- `review <pr>` — only in a fresh session that did not write the change: run `/code-review high` on the PR (plus `/security-review` when it changes sign-in, rights, secrets or tenancy/RLS) and post one PR comment with the findings, any breaking contract change or destructive migration, and a last line `Review verdict: pass` or `Review verdict: changes`. On `pass`, enable auto-merge (`gh pr merge <pr> --auto`) unless AGENTS.md, Merge rules needs a maintainer's accept; then say so in the comment instead.
- `ship` — if the PR needs a maintainer's accept (plan-tier plan, breaking contract change, destructive migration, `.github/`, `setup/`, or anything from the freeze, 2027-03-01), say which and stop; the maintainer labels it `accepted` and enables auto-merge. If the review verdict is `changes`, fix, push and ask for a new review. Otherwise wait until the verdict is `pass`, auto-merge is enabled and GitHub merges the PR (never `gh pr merge` without `--auto`). After merge: checkout main and pull; maintainers do the ready-chain bookkeeping.
- `pause` — update the PR description's `Next action:` line with where the work stands, push, stop.
- `resume` — checkout the issue's branch, read its PR description and continue from `Next action:`.
- `promote <n>` / `groom` (maintainers) — as in AGENTS.md, Maintainers; show proposals and change nothing until answered.
