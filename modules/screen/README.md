# screen

The venue screens ([contracts/screen.md](../../contracts/screen.md)). It holds the module's skeleton, devices with pairing, zones with assignments and mirroring (#220), device heartbeat and health (#222), playlists, schedule windows, pushes and the tick (#216), the asset library (#217), the ticker and photos (#218), and moving devices between events (#221); the player (#109) builds on it.

- **Stack:** Node 22, Fastify 5, `pg`, on `@canccu/kit` ([0006](../../docs/decisions/0006-stack.md)). Port 8080. Caddy routes `/api/screen/*` here unchanged and `/api/screen/health` to `/health`.
- **Env:** the kit's (`CANCCU_MODULE`, `CANCCU_VERSION`, `CANCCU_VALKEY_URL`, `CANCCU_ADMIN_URL`, `CANCCU_SERVICE_KEY`), plus `CANCCU_DATABASE_URL` (the login role it serves as), `CANCCU_MIGRATE_DATABASE_URL` (the migration role), `CANCCU_TENANTS_URL`, `CANCCU_SIGNIN_HOSTNAME`, `CANCCU_SUPERADMIN_HOSTNAME`, `CANCCU_IP_MODE` and, optionally, `CANCCU_FFPROBE` (the ffprobe binary; default `ffprobe` on the PATH).
- **Data:** `migrations/*.sql`, run at start by the kit's `runMigrations` (ledger `screen_migrations`). `devices` is the one global table (device identity only); every other table (`assignments`, `screen_zones`, `screen_zone_seeds`, `screen_playlists` with `screen_playlist_items`, `screen_schedules`, `screen_pushes`, `screen_zone_playback`, `screen_agenda_items`, `screen_assets`, `screen_asset_versions`, `screen_files`, `screen_ticker`, `screen_ticker_windows`, `screen_photos`, `screen_render_jobs`) is per event under RLS, and requests run as `canccu_screen_app`. Open pairing codes live in Valkey for 10 minutes, transfer codes and device commands for 60 seconds, device health (the last heartbeat, online deadlines and page loads) for up to 7 days; no device token is ever stored, only its SHA-256.
- **Scheduler core** (`src/schedule/`, pure, no routes yet): weekly windows in the event's time zone (`window.ts`), the winner among a zone's weekly and agenda-bound windows (`winner.ts`) and "what would play at…" with the next change (`simulate.ts`). Clock, time zone, the agenda items' times and the playlists' priorities come in as arguments, so the tick and the simulate route (#216) share one rule and the daylight-saving tests pin every input. Ported from the legacy signage `scheduler.ts` and `schedule-window.ts` with their tests; the calendar drag helpers go with Studio (#190).
- **Playback core** (`src/playback/`, pure, no routes yet): a playlist's timeline and frames with their progress-bar timing (`timeline.ts`, `engine.ts`); bookmarks that the tick pauses when a playlist stops and resumes when it plays again, so a deck comes back at its slide and no offset counts twice; a zone's `break` playlists as one state value the tick advances with `stepBreaks` (`breaks.ts`: due times, the daily window, priority chaining, the `break_min_gap_seconds` gap) and what a running break shows (`break-play.ts`: play-once, a looping timeline that goes on where the last break stopped, slideshow dwell with up to 10 s overrun, a shuffle seeded by zone, playlist and start). `projectBreaks` runs that step forward on a copy for simulate's `in_break` and `next_change_at`. Ported from the legacy signage `playback-engine.ts`, `playback-bookmark.ts`, `advt-scheduler.ts`, `advt-window.ts`, `advt-gap-settings.ts` and `advt-playback.ts` with their tests.
- **Content** (`src/content/`): playlists (one document with items, break settings and `revision`), schedule windows (weekly or bound to a run-of-show item, `revision` for conflicts), pushes and simulate (the windows and breaks at a time, not pushes, which play only now; breaks are projected about two weeks ahead at most), every write audited in its transaction. Bodies are checked in `input.ts` (ported from the legacy `api-schemas.ts` and the length and slide-range rules of `playlist-builder.ts`), and against the assets in `asset-rules.ts`: items and pushes name this event's assets, slide fields go only on decks, an automatic length only on video (a slideshow's images take its dwell), and a range ends within the rendered deck. A deck's ranges are clamped to it when a replace's render succeeds or a revert brings back a rendered version, and the playlists that change get a new `revision`. `agenda.ts` keeps `screen_agenda_items` from the `agenda.item.*` events, read from the streams' start at every boot, so bound windows follow delays, crew items included.
- **The tick** (`src/tick/`): every second, in every container, each zone of each event with screens advances once (`advanceZone`: the newest push above the winning window, bookmarks paused around breaks and switches, `stepBreaks`); a Valkey claim per zone and second gives each step to one container, and only a changed state is written to `screen_zone_playback`. It also ends expired pushes (`screen.content.cleared`, `reason: expired`, audited without an actor). Reads, simulate included, never write. Assets come through an `AssetReader`; until #217 supplies one nothing is playable, so breaks are skipped and bookmarks stay at the start.
- **Assets** (`src/assets/`): uploads are checked by content, never by name (`sniff.ts`); images are turned upright, fitted within 2560×1440 and re-encoded without metadata (`image.ts`, sharp); video and sound are probed with `ffprobe` (`probe.ts`), and anything the screens do not play is 400 `media_unsupported` with a message naming what was found and what to export. Files are content-addressed under `/files/<tenant>/screen/files/<sha256>.<ext>` (`files.ts`): written to `tmp/`, renamed into place, reserved against the event's storage quota at tenants first (`storage.ts`), shared by identical bytes, and deleted with the last row that refers to them, under a per-file advisory lock so a delete and an upload of the same bytes never cross. Once an hour per event, in one container (a Valkey claim), the storage upkeep (`upkeep.ts`) removes stored files without a row and the scratch (`tmp/render-<job>-<attempt>`) of render attempts no longer running, then sets screen's count at tenants to what its files, renders and running attempts take (the repair path); a writer holds a shared per-event lock from its reserve to its commit, so the recount never loses an upload under way. A replace keeps one undo version; version numbers are never reused. Web assets need an origin on `web_allowlist`, YouTube links become youtube-nocookie embeds with their oEmbed health; both need the `screen.web` flag. `GET /api/screen/files/{file}` serves the event's devices and `screen.content.read` sessions, with byte ranges. Ported from the legacy signage `asset-upload.ts`, `image-resize.ts`, `image-orientation.ts`, `video-duration.ts` (now ffprobe), `asset-replace.ts`, `asset-catalog.ts`, `web-asset.ts`, `youtube-asset.ts` and `youtube-oembed.ts` with their tests. Playlist items and active pushes keep an asset in use (`used_by` names them; a delete answers `asset_in_use`), and `readAssets` (`reader.ts`) gives the tick and simulate the assets' kind, length, slide count and health.
- **Ticker** (`src/ticker/`): a person's line (`PUT`, with an end or none) wins over the weekly ticker windows; among windows the one that began last shows, until its occurrence ends in the event's time zone (`resolve.ts`, pure, ported from the legacy `ticker-store.ts` without its read that deleted). Line and windows are kept in Postgres, so a restart loses neither. Every change of what the ticker shows is announced once as `screen.ticker.changed`: by the request that made it, or by the tick when a window starts or ends or a line runs out; the event's ticker row, locked by each, keeps two containers from announcing the same change. Window adds and deletes are audited. The pizza fallback line (`source: pizza`) is not built yet.
- **Photos** (`src/photos.ts`, flag `screen.photos`): images only, normalised as image assets are and stored as the event's content-addressed files, so a photo and an asset with the same bytes share one file and one quota count; listed newest first, `featured` until the player features it. A source's message (`source_ref`) is added once (409 `photo_exists`). `deleteUserPhotos` removes a deleted user's photos in one event. Ported from the API part of the legacy `carousel/photos.ts` with its tests.
- **Render jobs** (`src/render/`, #224, [plan](../../docs/plans/issue-184.md) slice B): a `pptx` or `pdf` upload or replace submits a job (`screen_render_jobs`, the truth), and `POST /api/screen/render-jobs` submits one again; a version's live job, or its render, answers a second submit. The fair queue (`queue.ts`) keeps each event's waiting jobs in a Valkey list and the events with any in a ring; the one renderer slot goes to the event at the head, which then moves to the back, so an event waits behind at most one job of each other event (Lua scripts, so a take is one step). A dispatcher in every container (`dispatch.ts`) takes the next job, streams its deck to `screen-render` over the `render-socket` volume (`client.ts`, which trusts nothing the renderer answers), reserves each slide's bytes against the quota before writing it, and renames the slides into `/files/<tenant>/screen/renders/<asset id>/<asset version>/` when the job is recorded as succeeded; anything else gives the bytes back. A job holds a 30-second lease, renewed every 5 seconds: a cancel is seen at the next renewal and hangs up on the renderer, and a lease that runs out (a lost container) puts the job back at the head of its event's list once, then fails it `renderer_failed`. A render goes with its asset version (a replace keeps the old one for the undo). The queue is rebuilt from Postgres per event, at most once a minute, when its jobs are read. `GET /api/screen/renders/…` serves the slides from the job row, never from a path in the request. The `render` health check is `degraded` while a deck has waited over 10 minutes. Threat model, a compromised renderer: it can only answer, and every answer is checked; one gap is known and low in impact: the socket's `lstat` then `connect` is check-then-use, so the renderer, the only writer of its volume, could swap a link in between, which reaches only Unix sockets in screen's own filesystem (never a file) and is sent only the deck. `CANCCU_RENDER_SOCKET` overrides the socket path (default `/run/canccu-render/render.sock`).
- **Settings:** declared in `modules/admin/declarations/screen.yaml`, read through the kit's settings client. `offline_after_seconds` counts as at least twice `heartbeat_seconds`, so one late heartbeat never takes a screen offline; while admin is down the defaults hold.
- **Routes so far:** `POST`, `DELETE /api/screen/pairing`, `GET /api/screen/pairing/{pairing_id}`, `GET`, `POST /api/screen/devices`, `PATCH /api/screen/devices/{device_id}`, `POST /api/screen/devices/{device_id}/revoke`, `POST /api/screen/device/heartbeat`, `GET /api/screen/device/home`, `POST /api/screen/device/transfer`, `GET /api/screen/registry/devices`, `PATCH`, `DELETE /api/screen/registry/devices/{device_id}`, `PUT`, `DELETE /api/screen/devices/{device_id}/assignment`, `POST /api/screen/devices/{device_id}/commands`, `GET`, `POST /api/screen/zones`, `GET`, `PUT`, `DELETE /api/screen/zones/{zone_key}`, `GET`, `POST /api/screen/playlists`, `GET`, `PUT`, `DELETE /api/screen/playlists/{playlist_id}`, `GET`, `POST /api/screen/schedules`, `PUT`, `DELETE /api/screen/schedules/{schedule_id}`, `GET /api/screen/schedules/simulate`, `POST /api/screen/push`, `DELETE /api/screen/push/{push_id}`, `GET`, `POST /api/screen/assets`, `POST /api/screen/assets/name-check`, `PATCH`, `DELETE /api/screen/assets/{asset_id}`, `POST …/replace`, `POST …/revert`, `GET /api/screen/files/{file}`, `GET`, `POST /api/screen/render-jobs`, `GET`, `DELETE /api/screen/render-jobs/{job_id}`, `GET …/{job_id}/result`, `GET /api/screen/renders/{asset_id}/{asset_version}/{slide}`, `GET`, `PUT`, `DELETE /api/screen/ticker`, `GET`, `POST /api/screen/ticker/windows`, `DELETE …/{window_id}`, `GET`, `POST /api/screen/photos`, `DELETE /api/screen/photos/{photo_id}`. `requireDevice` (`src/device-access.ts`) is the check the device routes of later slices run; `takeCommands` (`src/assignments.ts`) is what the push channel (#109) delivers, and `ZONE_USES` (`src/zones.ts`) lists what keeps a zone in use (screens, windows, pushes, break playlists).
- **Health** (`src/health.ts`): every heartbeat moves the device's deadline (the heartbeat plus `offline_after_seconds`) in one Valkey set per event; a sweep in every container, every 5 seconds, takes the passed deadlines and emits `screen.device.offline` once each. `GET /api/screen/devices` shows each device's `health` with the `clock_drift` and `shared_token` flags. `state_lag` waits for the zone's state version, which the composed state (#109) brings.
- **Moving** (`src/registry.ts`, `src/moving.ts`): the superadmin's registry answers only on `CANCCU_SUPERADMIN_HOSTNAME`, and there only to a session admin marks `superadmin`; elsewhere it is 404 before any sign-in check, and on the platform hostnames every other route is 404. A move runs in one transaction that binds the old event and then the new one in turn (`asTenant`): the old side unassigns the device, its mirrors and its zone's sound (`detachDevice`), the new side gives it a place without a zone; the audit entry is a platform one. A moved kiosk's `GET /api/screen/device/home` answers the new event's screen URL; the current token also gets a transfer code (60 seconds, single use, in the new event's Valkey keys, made for that one token), which `POST /api/screen/device/transfer` swaps for a new token and cookie, keeping the replaced token as superseded for 7 days. The event left behind forgets the device's health.
- **Zones:** an event gets its `main` zone once, on `tenants.tenant.created` or its first zone, assignment or pairing request, whichever comes first; a deleted `main` is not made again. `detachDevice` (`src/detach.ts`) is the one place that clears mirrors and sound devices when a device leaves the event.

- **Cookies** `canccu_pairing` and `canccu_device` are always `Secure`, as the contract says, so browsers keep them only over HTTPS: the IP-mode demo stack (plain http on port 80) cannot pair a real kiosk until TLS (#5). The tests send the cookies themselves.

## Check

```sh
npm ci && npm run lint && npm run typecheck && npm test
```

The media tests run the real `ffprobe`: `CANCCU_FFPROBE` if set, otherwise the build of the `@ffprobe-installer/ffprobe` dev dependency, so they need no ffmpeg on the machine. The tests need a Postgres for RLS and skip without one. Point `CANCCU_DATABASE_URL` at a throwaway database (the tests drop and recreate the screen tables) as a superuser; requests still run as the app role, which RLS binds:

```sh
docker run -d --rm --name canccu-screen-test -e POSTGRES_PASSWORD=test -p 127.0.0.1:55432:5432 postgres:17.11-alpine
CANCCU_DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/postgres npm test
docker stop canccu-screen-test
```

With `CANCCU_VALKEY_URL` set, the render-queue tests also run the Lua scripts against that Valkey, in its database 15, which they empty. `test/render-smoke.mjs` renders a PDF through the screen container's own client and socket mount against the real renderer; CI's compose job runs it.

CI runs them against its own Postgres in the `module (screen)` job ([docs/ci.md](../../docs/ci.md#modules)).
