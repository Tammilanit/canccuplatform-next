# screen

The venue screens ([contracts/screen.md](../../contracts/screen.md)). It holds the module's skeleton, devices with pairing, zones with assignments and mirroring (#220), device heartbeat and health (#222), and the asset library (#217); moving devices (#221), the rest of the content (#108) and the player (#109) build on it.

- **Stack:** Node 22, Fastify 5, `pg`, on `@canccu/kit` ([0006](../../docs/decisions/0006-stack.md)). Port 8080. Caddy routes `/api/screen/*` here unchanged and `/api/screen/health` to `/health`.
- **Env:** the kit's (`CANCCU_MODULE`, `CANCCU_VERSION`, `CANCCU_VALKEY_URL`, `CANCCU_ADMIN_URL`, `CANCCU_SERVICE_KEY`), plus `CANCCU_DATABASE_URL` (the login role it serves as), `CANCCU_MIGRATE_DATABASE_URL` (the migration role), `CANCCU_TENANTS_URL`, `CANCCU_SIGNIN_HOSTNAME`, `CANCCU_SUPERADMIN_HOSTNAME`, `CANCCU_IP_MODE` and, optionally, `CANCCU_FFPROBE` (the ffprobe binary; default `ffprobe` on the PATH).
- **Data:** `migrations/*.sql`, run at start by the kit's `runMigrations` (ledger `screen_migrations`). `devices` is the one global table (device identity only); every other table (`assignments`, `screen_zones`, `screen_zone_seeds`, `screen_assets`, `screen_asset_versions`, `screen_files`) is per event under RLS, and requests run as `canccu_screen_app`. Open pairing codes live in Valkey for 10 minutes, device commands for 60 seconds, device health (the last heartbeat, online deadlines and page loads) for up to 7 days; no device token is ever stored, only its SHA-256.
- **Scheduler core** (`src/schedule/`, pure, no routes yet): weekly windows in the event's time zone (`window.ts`), the winner among a zone's weekly and agenda-bound windows (`winner.ts`) and "what would play at…" with the next change (`simulate.ts`). Clock, time zone, the agenda items' times and the playlists' priorities come in as arguments, so the tick and the simulate route (#216) share one rule and the daylight-saving tests pin every input. Ported from the legacy signage `scheduler.ts` and `schedule-window.ts` with their tests; the calendar drag helpers go with Studio (#190).
- **Playback core** (`src/playback/`, pure, no routes yet): a playlist's timeline and frames with their progress-bar timing (`timeline.ts`, `engine.ts`); bookmarks that the tick pauses when a playlist stops and resumes when it plays again, so a deck comes back at its slide and no offset counts twice; a zone's `break` playlists as one state value the tick advances with `stepBreaks` (`breaks.ts`: due times, the daily window, priority chaining, the `break_min_gap_seconds` gap) and what a running break shows (`break-play.ts`: play-once, a looping timeline that goes on where the last break stopped, slideshow dwell with up to 10 s overrun, a shuffle seeded by zone, playlist and start). `projectBreaks` runs that step forward on a copy for simulate's `in_break` and `next_change_at`. Ported from the legacy signage `playback-engine.ts`, `playback-bookmark.ts`, `advt-scheduler.ts`, `advt-window.ts`, `advt-gap-settings.ts` and `advt-playback.ts` with their tests; storing the state and the tick are #216's.
- **Assets** (`src/assets/`): uploads are checked by content, never by name (`sniff.ts`); images are turned upright, fitted within 2560×1440 and re-encoded without metadata (`image.ts`, sharp); video and sound are probed with `ffprobe` (`probe.ts`), and anything the screens do not play is 400 `media_unsupported` with a message naming what was found and what to export. Files are content-addressed under `/files/<tenant>/screen/files/<sha256>.<ext>` (`files.ts`): written to `tmp/`, renamed into place, reserved against the event's storage quota at tenants first (`storage.ts`), shared by identical bytes, and deleted with the last row that refers to them, under a per-file advisory lock so a delete and an upload of the same bytes never cross. A replace keeps one undo version; version numbers are never reused. Web assets need an origin on `web_allowlist`, YouTube links become youtube-nocookie embeds with their oEmbed health; both need the `screen.web` flag. `GET /api/screen/files/{file}` serves the event's devices and `screen.content.read` sessions, with byte ranges. Ported from the legacy signage `asset-upload.ts`, `image-resize.ts`, `image-orientation.ts`, `video-duration.ts` (now ffprobe), `asset-replace.ts`, `asset-catalog.ts`, `web-asset.ts`, `youtube-asset.ts` and `youtube-oembed.ts` with their tests. Renders and the render job are #224's, playlists (and `used_by`, `asset_in_use` for them) #216's.
- **Settings:** declared in `modules/admin/declarations/screen.yaml`, read through the kit's settings client. `offline_after_seconds` counts as at least twice `heartbeat_seconds`, so one late heartbeat never takes a screen offline; while admin is down the defaults hold.
- **Routes so far:** `POST`, `DELETE /api/screen/pairing`, `GET /api/screen/pairing/{pairing_id}`, `GET`, `POST /api/screen/devices`, `PATCH /api/screen/devices/{device_id}`, `POST /api/screen/devices/{device_id}/revoke`, `POST /api/screen/device/heartbeat`, `PUT`, `DELETE /api/screen/devices/{device_id}/assignment`, `POST /api/screen/devices/{device_id}/commands`, `GET`, `POST /api/screen/zones`, `GET`, `PUT`, `DELETE /api/screen/zones/{zone_key}`, `GET`, `POST /api/screen/assets`, `POST /api/screen/assets/name-check`, `PATCH`, `DELETE /api/screen/assets/{asset_id}`, `POST …/replace`, `POST …/revert`, `GET /api/screen/files/{file}`. `requireDevice` (`src/device-access.ts`) is the check the device routes of later slices run; `takeCommands` (`src/assignments.ts`) is what the push channel (#109) delivers, and `ZONE_USES` (`src/zones.ts`) is where #108 adds its own `zone_in_use` checks.
- **Health** (`src/health.ts`): every heartbeat moves the device's deadline (the heartbeat plus `offline_after_seconds`) in one Valkey set per event; a sweep in every container, every 5 seconds, takes the passed deadlines and emits `screen.device.offline` once each. `GET /api/screen/devices` shows each device's `health` with the `clock_drift` and `shared_token` flags. `state_lag` waits for the zone's state version, which the composed state (#109) brings.
- **Zones:** an event gets its `main` zone once, on `tenants.tenant.created` or its first zone, assignment or pairing request, whichever comes first; a deleted `main` is not made again. `detachDevice` (`src/detach.ts`) is the one place that clears mirrors and sound devices when a device leaves the event.

- **Cookies** `canccu_pairing` and `canccu_device` are always `Secure`, as the contract says, so browsers keep them only over HTTPS: the IP-mode demo stack (plain http on port 80) cannot pair a real kiosk until TLS (#5). The tests send the cookies themselves.

## Check

```sh
npm ci && npm run lint && npm run typecheck && npm test
```

The media tests run the real `ffprobe`: `CANCCU_FFPROBE` if set, otherwise the build of the `@ffprobe-installer/ffprobe` dev dependency, so they need no ffmpeg on the machine. The tests need a Postgres for RLS and skip without one. Point `CANCCU_TEST_DATABASE_URL` at a throwaway database (the tests drop and recreate the screen tables) as a superuser; requests still run as the app role, which RLS binds:

```sh
docker run -d --rm --name canccu-screen-test -e POSTGRES_PASSWORD=test -p 127.0.0.1:55432:5432 postgres:17.11-alpine
CANCCU_TEST_DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/postgres npm test
docker stop canccu-screen-test
```

CI runs them against its own Postgres in the `module (screen)` job ([docs/ci.md](../../docs/ci.md#modules)).
