# 0018. The ticker is manual: set by a person, from admin or the bot

- **Status:** Accepted (supersedes the ticker line of [0010](0010-scope.md))
- **Date:** 2026-11-06

## Context
[0010](0010-scope.md) drops "the RSS ticker and automatic ticker posts (the ticker stays, manual only)". "Manual only" can be read as "from the admin UI only", which would drop the bot's `/ticker` commands. The legacy bot also has scheduled ticker windows (`/ticker schedule add|list|remove`), which 0010 does not place on either side; the [canccubot inventory](../legacy-inventory/canccubot.md#tenancy-questions) asks about them in question 10. Legacy keeps those windows in memory, so a restart loses them.

## Decision
- **Manual means set by a person.** A person sets the ticker from the admin UI **or** from the bot's `/ticker` commands (`set`, `stop`, `status`). The bot command stays as a courtesy, so the ticker can be set from Discord. The bot publishes to Screen; it holds no ticker state of its own.
- **Scheduled ticker windows count as manual:** an admin sets them in advance. They are ported into Screen's scheduler windows. The bot keeps its schedule commands (`/ticker schedule add|list|remove`), which publish to Screen.
- **Still dropped:** the RSS ticker, and automatic ticker posts (posts generated by the system, not by a person).

The rest of 0010 stands.

## Consequences
- Screen core ([roadmap step 3](../roadmap.md#3-screen-core-incl-pptx)) owns the ticker and its scheduled windows, and keeps the windows across restarts (in Postgres, [0007](0007-stateless-containers.md)).
- The bot ([roadmap step 6](../roadmap.md#6-bot)) ports `/ticker set|stop|status` and the schedule commands as publishers to Screen; the event names and payloads are the event catalog's to decide.
- Question 10 of the canccubot inventory is answered.
