1 · Design language

One page that shows them all

Every surface draws from the same eleven colour tokens, four fonts and four sizes that packages/ui already has. Nothing new is a token: tints, hovers and raised surfaces are mixed from the tokens, so an event's theme (or the light scheme) restyles every page at once. Try the switch at the top right.

Colour

Eleven tokens, one job each

Primary is for the one thing to do (and links and focus). Accent marks highlights only: the avatar, a featured item. Status colours mean status and nothing else: the "now" line is primary, not red (F2). Text on a colour fill uses primary_text.

Fonts are the theme's: heading for titles, body for the rest, display on screens, mono for codes. Numbers that change (times, counts) are tabular, so they don't jump.

2 · Organiser shell

One header, one Event menu, one content column

Every organiser page, whichever module serves it, is drawn by one page() shell from packages/ui: the event's header across the top, the Event menu at the side, the page's own sub-pages as a row of tabs, and the content at one of two widths. The menu lists every page this person may open, marks the current one and ends with Sign out. On a phone the same menu opens from the header.

9 · Screens

The device frames are one family with Pulse

Every frame a screen can show is built from Pulse's parts (mockups 02–05): the same header (logo, event name, zone or device, clock), the same background with its soft glow, the same display type and panels. A screen going from pairing to not assigned to Pulse never changes colour, and the clock never jumps corners. Drawn at 1920×1080, shown smaller; the switch at the top recolours them like the pages.
