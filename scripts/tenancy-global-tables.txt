# Global tables: no tenant_id, no RLS, read before a tenant is set (0013 item 6; checked by
# scripts/check-tenancy, docs/ci.md#tenancy). Every other table in modules/*/migrations is a
# tenant table. One entry per line: <module> <table> <reason>. An entry without a reason exempts
# nothing. A new global table needs a change here, so the review sees it; a global row holds no
# tenant-scoped data beyond a plain tenant reference.
tenants tenants         the registry row of every event (contracts/tenants.md, Tables)
tenants hostnames       each hostname and its tenant as a plain reference, also held ones
tenants venues          venues are shared by events and managed by the superadmin
tenants users           users are global (0013 item 30)
tenants series          a series spans events
tenants platform_audit  audit entries that belong to no single event
tenants tenants_migrations which migration files ran (created by db.py before the files); no event data
admin admin_migrations  which migration files ran (created by db.py before the files); no event data
admin admin_users       sign-in accounts; sign-in is not per tenant until the central sign-in host (#52)
admin admin_roles       the owner and admins of today's single sign-in; per tenant with #52
admin admin_sessions    sign-in sessions, hashed; each is bound to one tenant with #52
admin admin_sign_in_flows OAuth flows in progress, hashed; no event data
admin admin_first_run   the one-time first-run code, hashed; no event data
screen devices          device identity: name, token hash, venue id, current tenant (0013 item 34)
screen screen_migrations which migration files ran (created by runMigrations before the files); no event data
screen screen_pin_tenants the events whose pin holds anything, a plain tenant reference, so the tick and the bundle retention find them without a tenant set
agenda agenda_timer_tenants the events with pending timers, a plain tenant reference, so the scheduler finds them without a tenant set
agenda agenda_outbox_tenants the events with pending outbox rows, a plain tenant reference, so the sender finds them without a tenant set
notify notify_migrations which migration files ran (created by db.py before the files); no event data
notify notify_topic_types the topic registry: one set of topic types for the platform (contracts/notify.md, Tenancy)
notify notify_topic_type_history every registration change, append-only; module registrations, no event data
notify notify_outbox_tenants the events with pending outbox rows, a plain tenant reference, so the sender finds them without a tenant set
notify notify_delivery_tenants the events with deliveries waiting, a plain tenant reference, so the sender finds them without a tenant set
notify notify_agenda_tenants the events whose quiet hours notify mirrors, a plain tenant reference, so start-up reads each agenda again without a tenant set
